Implementation outline and interfaces
-------------------------------------
Keep the existing Tracks path and v2 resolver path separate. Do not route a
resolver result through numeric Tracks IDs or the current Tracks URL validator.
The following pseudocode defines the proposed boundary, not implemented code:

```text
enum ResolverKind { Tracks, UnifiedV2 }

resolve(route, query):
  match route:
    Tracks    -> existing Tracks search/resolve path (unchanged)
    UnifiedV2 -> UnifiedV2Resolver.resolve(query)

struct ResolverEndpoint {
  base_url: Url
  schema_versions: Set<u32>
  auth_mode: AuthMode
  enabled: bool
}

struct ResolverConfig { endpoint: ResolverEndpoint } // no mirror pool at launch

struct ResolverQuery {
  title: String
  artist: Optional<String>
  album: Optional<String>
  isrc: Optional<String>
  duration_seconds: Optional<u32>
  intent: "stream"
  quality: Quality
}

struct ResolvedTrack {
  identity: ResolverIdentity       // title, artists[], album, ISRC, optional duration
  source: ResolverSource           // e.g. Amazon; opaque provider ID, never Tracks ID
  resource: PlaybackResource       // selected direct media only
}

struct PlaybackResource {
  url: SecretUrl                   // memory only; never cache or serialize
  mime: "audio/mp4"
  container: "mp4"
  codec: "flac"
  quality: Quality
  encryption: CencAesCtr { key_bytes: Secret<[u8; 16]>, iv_metadata: ProviderIvMetadata }
  generation: ResourceGeneration  // replaced only by a fresh successful resolve
}

interface ManagedWebViewResolverBridge {
  resolve_selected_row(query, quality, cancellation)
    -> Result<ResolverEnvelope, ResolverFailure>
}

interface UnifiedV2Resolver {
  resolve(query, quality, managed_page, cancellation)
    -> Result<ResolvedTrack, ResolverFailure>
}

enum ResolverFailure {
  NoMatch, AuthRequired, Forbidden, EdgeBlocked, RateLimited,
  Transport, RetryableServer, InvalidSchema, Unsupported, IdentityMismatch
}
```

The request shape in the pinned browser source and Alvafro capture is GET
`/api/v2/track/?track=…&artist=…&album=…&isrc=…&duration=…&intent=stream&quality=…`;
omit absent optional fields, round duration to seconds, and use the canonical
quality token. The pinned client sends `Accept: application/json`,
`Authorization: Bearer …`, and optional `X-Turnstile-JWT`; it uses no-store and
a bounded timeout. The capture confirms query fields and auth-header presence,
not secret values or how the Turnstile exchange produced them. Never forward
either auth header to the CDN.

The proposed credential boundary is a managed-WebView bridge: the page performs
the normal official-site bootstrap and resolver request, then returns only the
matched response and ephemeral playback material needed by the native session.
This bridge is not yet demonstrated. The pinned production app does not expose
a resolver method on `window.monochrome`; the inspected global only exposes
development classes, so do not assume an existing-method bridge. Do not export
browser-profile credentials or persist captured secrets. Native HTTP remains
out of scope until a supported native credential flow and ordinary edge access
are demonstrated. Direct no-proxy requests are currently edge-blocked by
browser signature; classify that separately from 401/403 returned by the API
after reaching it, and do not try to defeat the edge block.

The following verification sequence is from the pinned frontend's `api.js`;
it does not establish the auth flow in the newer official site or captured
Firefox deployment. In particular, the fresh WebKit official-site probe loaded
no Turnstile script or challenge frame:
1. The configured default-key client requests a Turnstile challenge in the real
   website context, displaying the interactive challenge when required.
2. POST /api/auth/turnstile with the configured Bearer credential and JSON
   {"turnstile_token": "<fresh challenge response>"}. Keep these values within
   the authorized browser session. The frontend accepts access_token, jwt, or
   token in the response and sends it as X-Turnstile-JWT on resolver requests.
3. The frontend uses JWT exp with a 15-second early-expiry margin; its one-hour
   fallback when exp is absent is a client assumption, not a server guarantee.
   Coalesce concurrent verification attempts rather than presenting duplicates.
4. A first 401 or 428 clears the cached JWT and forces one verification retry.
   A custom configured API credential is tried without a new challenge on the
   initial request, but server acceptance of that branch is unverified here.
5. A 429 respects Retry-After. Do not rotate mirrors to evade a shared limit.
The actual captures confirm the resolver's Bearer/JWT header combination, not
the issuance response or native acceptance of these browser credentials. A
production browser transport still needs a deliberate credential/session
interface; the public app does not expose a ready-made production resolver
method that can simply be called from the companion.

Parse one authoritative top-level `playback[]` resource. The captured response
also duplicates that resource in `sources[].resources[]`; do not resolve or
consume the duplicate. Require schema_version 2, a track object, selected_source,
and a coherent resource with kind=audio, delivery=direct, matching source, and
the expected container/codec. Preserve `track.artists[]`, title, album and ISRC
independently from transport; `duration_ms` may be null and stays unknown. Keep
Amazon ASINs and other resolver IDs in an opaque typed namespace. Compare ISRC,
title, full artist credit and album/version against the requested recording; do
not accept an echoed ISRC by itself. For CENC, accept only the verified
`cenc-aes-ctr` scheme and hex encoding that decodes to exactly 16 key bytes;
reject unknown key encoding or IV semantics until verified. Never persist the
media URL or key.

Map failures before fallback policy: 429 is RateLimited and honors Retry-After;
401/403 from the API is AuthRequired/Forbidden; the observed Cloudflare 403 is
EdgeBlocked, not an auth result; a 404 is NoMatch only when its response schema
confirms that meaning, otherwise it is EndpointOrProtocolError; malformed or
unknown schema is InvalidResponse. With one launch endpoint, return transport,
server, rate-limit, edge-block and auth failures to existing-provider fallback
scheduling and diagnostics. Add a resolver mirror only after independently
verifying its v2 schema and authorized session behavior, in later user-approved
scope; never rotate on identity mismatch or silently downgrade auth failures.

Resolve a fresh resource before each new playback. Keep its URL, key and
generation only in the active playback session. Seek within that session using
the same ranged resource; if it expires or fails, resolve once again and resume
at the last confirmed position. Do not retain a URL/key across tracks, queue
items or restarts. Preserve API auth only for the resolver host; media requests
use the returned URL and range headers without resolver credentials.

Implementation plan after the hold is released
-----------------------------------------------
1. Build the dedicated managed WebView transport on the official site origin,
   with its own profile and normal verification flow. Keep API credentials in
   the page context and expose only matched metadata and the ephemeral resource
   through a narrow bridge. A browser addon is a fallback only if fresh-profile
   WebKit cannot complete that flow. Do not begin until the gates above pass and
   the user explicitly releases the hold. No mirror pool at launch.

2. Add a distinct typed resolver adapter. Input is recording evidence and target
   quality; output separates matched identity, underlying source, transport and
   measured quality. Keep resolver identity distinct from the existing Tracks
   provider IDs. Never coerce Apple IDs into numeric Tracks IDs or broaden the
   current Tracks URL validator globally. Integrate at the shared acquisition
   and playback boundary so catalog, radio, queue and later download use agree.
   Qualify download semantics separately before enabling batch downloads.

3. Feed actual returned recording evidence through the shared matcher in all
   three modes. A request ISRC echoed in a response is not independent proof.
   Keep confidence/provenance and missing evidence explicit. Do not loosen
   identity checks simply because a candidate offers FLAC. Preserve full credits
   and version information; consult the existing track-matching plan.

4. Carry the selected direct FLAC/MP4 resource and its CENC key in an ephemeral
   playback context. Never place the key in FFmpeg argv or diagnostics. A synthetic
   n9.0.2 probe established two viable handoffs: (a) a small native libavformat
   helper accepts the 16 raw key bytes over a pipe and sets `decryption_key` in
   memory; packet reads succeeded with no key in argv/logs, or (b) FFmpeg's concat
   demuxer accepts an ffconcat manifest with `option decryption_key <hex>` sent
   through stdin or an inherited pipe. The pipe-manifest probe decoded ordinary
   and fragmented MP4 to exact reference PCM (264600 bytes); input-side and
   output-side one-second seeks each matched the clear reference (176400 bytes).
   It kept the key off disk, argv and stderr. Use fully qualified child URLs
   (`file:/absolute/path` in the probe, HTTPS URL for remote delivery); a bare
   absolute path over the pipe was mis-resolved as `pipe:/...`. Keep protocol
   allowlists, TLS, redirects, Range, cancellation, and output safety explicit.
   The simpler ffconcat path is a candidate for the current CLI; the helper avoids
   subprocess parsing and is a second option. The separate live probe confirms
   the supplied Alvafro and Bacc key/resource pairs decode and seek for the
   measured samples, but does not validate the shipped FFmpeg build, full-track
   or device playback, resolver acquisition, or production secret lifecycle.
   Evidence:
   docs/performance-results/2026-10-21-monochrome-resolver/key-handoff-probe.json,
   concat-key-handoff-probe.json, and concat-key-handoff-pipe-probe.json. See
   FFmpeg's [concat demuxer](https://www.ffmpeg.org/ffmpeg-formats.html#concat)
   and [MOV demuxer](https://ffmpeg.org/ffmpeg-formats.html#mov_002fmp4_002f3gp).

   Burrata's AudioSource currently has no typed media-encryption context. Add
   ephemeral key ownership and guaranteed disposal at playback-session end or
   failure, and audit subprocess arguments, diagnostics, crash reports and temp
   files. Qualify this integration with the shipped FFmpeg and playback session
   lifecycle; the standalone live decode/seek proof is already recorded above.

   Concrete native_output.rs change: decode_ffmpeg_with_diagnostics currently
   uses `.stdin(Stdio::null())` and `-i source.input`. For this typed resource,
   use piped stdin, `-f concat -safe 0 -i pipe:0`, and write then close a bounded
   in-memory manifest before consuming PCM. Preserve the existing stdout PCM,
   cancellation, child reaper and position handling. `-nostdin` can remain: it
   disables interactive controls, not media input on pipe:0. Manifest shape:

     ffconcat version 1.0
     file '<validated, correctly escaped HTTPS media URL>'
     option decryption_key <32 hex characters from the ephemeral 16-byte key>
     option rw_timeout 5000000

   Pass a narrow protocol whitelist (pipe,https,tls,tcp,crypto for these live
   resources). Treat ffconcat as a language: reject CR/LF/NUL in input, escape
   its quoting correctly, and never interpolate unchecked response text as
   directives. Do not set a fabricated duration when duration_ms is null; the
   tested MP4 demuxer discovers it. Keep both the URL and key out of argv.
   Error paths must redact media URLs/key material before retaining FFmpeg
   stderr; the current safe_failure_text path needs explicit coverage for this
   source. Add per-child HTTP options to the manifest rather than assuming an
   outer concat option reaches its child demuxer. HTTP timeout forwarding still
   needs a controlled timeout fixture; the live probe established decoding and
   seeking, not all transport error handling.

   Use one resolver lookup for identity plus the selected audio resource, and
   inspect that same resource for playback. Reject unsupported delivery clearly.
   Validate TLS, destinations and redirects; never forward API credentials to
   an audio CDN. Native FLAC decoding alone does not qualify encrypted MP4.

5. Use fresh transport resolution for each playback when required. Cache stable
   recording/source evidence independently from expiring transport state. Include
   source, policy version and proof freshness in reuse decisions. Avoid caching
   auth/DNS/rate-limit failures as permanent recording misses. Coalesce overlapping
   work, bound retries and cancellation, and respect the global playback deadline.

6. Make quality preference explicit in scheduling. Prepare fallback concurrently,
   but allow a bounded lossless-resolution budget when lossless is preferred.
   Do not silently change the meaning of the existing 1500 ms setting. Preserve
   explicitly selected sources and existing cancellation/queue behavior. Report
   whether fallback occurred because of no match, unsupported transport, auth,
   DNS, rate limiting or deadline. Do not switch streams mid-song unexpectedly.
   A cached YouTube mapping must not permanently suppress a new preferred route.

7. Extend queue preparation after basic playback is proven. Prepare identity and
   stable evidence early; resolve ephemeral resources close enough to consumption
   to avoid expiry. Measure cold and warm startup plus fallback latency, endpoint
   requests and cancellations. Generalize to a held-out set of recordings that
   the website can play losslessly but Burrata currently resolves to YouTube.

Temporary Firefox capture
-------------------------
scripts/monochrome-research builds an opt-in temporary companion at
.cache/monochrome-research-extension/manifest.json. It observes page fetch/XHR
JSON after injection, strips credentials/media URLs/keys before export, and
stops observing after five minutes. Requests made earlier or inside another
realm/service worker are outside that observer's coverage.

The user approved the org.burrata.monochrome_research native sink, which
accepted bounded sanitized reports at fixed local paths and had no network
listener or command execution interface. Clicking the extension's activeTab
action resolved page visibility and enabled capture of the three resolver
responses above. The saved observation records stopped=false. The observer is
configured to stop after five minutes, but shutdown was not independently
verified. The temporary native-messaging registration JSON has been removed;
the helper can no longer be launched by Firefox through that registration.
The temporary companion itself remains loaded and can be removed from Firefox's
about:debugging page. Its generated extension manifest was not deleted.
