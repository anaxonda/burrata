# WebView manual seek completion deadline

A manual WebView seek previously reset steady buffering recovery and relied on seeked/error events. If neither arrived, the seek had no completion deadline. The integrated change adds an owner-bound20-second deadline for finite-source manual seeks. Ownership includes the exact audio node and source object, source generation, seek serial, playback session, track and queue occurrence. Pausing suspends the deadline; resuming arms it. A new seek replaces the old target. Source replacement, stop, error, end and unmount cancel stale work. Startup/recovery seeks use their existing budget and explicitly opt out.

Completion requires the current node to stop seeking and land near the requested target. A wrong-position seeked event does not clear the deadline or refresh recovery state. Successful completion/resume restores the steady media-clock monitor only after a completed playback attachment. On timeout, the requested target—not a reset media clock—is passed into existing position-preserving recovery. Only previously healthy playback may renew that recovery deadline, tied to the captured request; the two-attempt limit is preserved. Ineligible source kinds or invalid positions fail visibly while retaining the requested position for explicit retry. Supported manual seeks remain available while media duration is unknown; the same completion deadline is armed. If actual duration is still unavailable at expiry, recovery fails closed at the requested target. Invalid/nonfinite targets are rejected before changing seek ownership or media position.

## Compatibility correction during integrated verification

The final mounted App run exposed that the proposed pre-mutation duration guard was too restrictive: several existing chapter, paused-resume and identification flows support seeking before actual media metadata arrives. That guard has been replaced, without changing those existing compatibility fixtures. The intended policy is to honor the source's canSeek capability and arm the same owner/target deadline even while duration is unknown. If metadata never permits recovery, the existing requested-position timeout path fails closed instead of restarting at zero. The current running app still predates this seek patch. The integrated run retains368 passing/8 failing results; one unrelated history test timed out during overlapping checks/build and needs reevaluation without concurrent heavy work. No failed run is counted as completed acceptance.
