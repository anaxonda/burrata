# Spotify profile-summary diagnostic

This change adds a read-only summary mode to the existing profile inspection tool. It compares an independently documented WebPlayer full-profile protobuf route with the existing paged route; it does not replace normal browsing or infer completeness from totals.

The pinned WebPlayer codec has URI field 1, repeated playlist messages at field 8 and reported total at field 9. The worker formerly preserved binary data only for playlist-suffixed routes. It now preserves bytes on the exact profile-root route only under diagnostic metadata and the existing strict HTTP allowlist. Summary parsing reuses the bounded playlist decoder, caps 200 rows/2 MiB, and emits ordered domain-separated ID hashes instead of raw IDs or response content. Proto3 URI-only/default-zero, invalid known-field wire type, JSON MIME and oversize fixtures are covered.

Root validation: 56 worker tests, 17 adapter tests, 945 native tests (21 ignored), and 8 contract checks pass. Native tests initially failed 28 socket/subprocess OS-permission boundaries under sandbox; the required-access rerun passed all tests in 16.58 seconds. Logs: `.cache/profile-summary-root-{worker-tests,adapter-tests,native-tests,native-host-tests,contracts}.log`. Six reviewed source hashes are in `.cache/profile-summary-source-pin.json`. The executable built in 2m00s, with immutable SHA `fc32d24cf4e55de8c1cd5e0d6c13b3103eda95732d92b3e15c0bab8d5c4a1af9`; all 515 source inputs were rechecked. The sole normal app relaunched with an exactly equal fresh queue/settings snapshot. Live read-only comparison for the user-supplied profile completed: the summary returned 99 unique hashed playlist IDs, reported total 179, and HTTP 200. Four paged reads returned 30/30/29/10 rows with reported totals 110/110/109/90. Both paths returned the exact same 99 IDs in the same order, with zero additional IDs in either direction. Neither route proves complete reachability; changing production pagination to the summary route would add no playlists in this observation. The varying reported totals remain unreliable as completion evidence. Sanitized counts: `.cache/qualification-profile-summary/live-comparison-counts.json`; raw diagnostic outputs contain only bounded structure and ID hashes. No new profile-browsing completeness claim is made.

No provider writes, profile imports, playlist membership changes or production pagination changes occurred during these checks.
