# Disconnected Burrata player layout fixture

This isolated Vite page imports the current app-wide, desktop-layout, and player stylesheets and mounts the real TrackList, PlaybackQueuePanel, PlayingInfo, PlaybackQuality, and SeekSlider components with synthetic data. The footer follows App's current control order and classes, including radio autoplay, quality/source text, the real seek slider, and queue/details actions. The main header uses App's back/forward, title, and New playlist control pattern. It does not import App.svelte, Tauri APIs, production storage, or browser automation hooks. This is limited disconnected component/layout evidence, not full App/Tauri integration evidence.

The fixture was rendered in isolated headless Chromium with a fresh `/tmp` profile. Query states: `state=playing|buffering|paused|unavailable`, `panel=queue|details`, and `identify=active`. Screenshots use 360x800, 500x900, 1000x800, and 1440x900. `controls=1` enables fixture buttons; omit it in screenshots.

Final captures are `/tmp/burrata-ui-*-final.png`. They cover long-title playback at each width; idle and active Identify in queue; paused state and active Identify progress in details; and unavailable playback/error with details. Visual review found the footer stays visible; player title, quality, and source text clip within their compact region; Identify and Cancel/progress fit; the queue/details panel stops above the footer; and no obvious horizontal overflow or control overlap appears at these widths. The unavailable error adds a second footer row without obscuring transport. This is visual inspection only, without DOM geometry assertions.

The first render attempt used `new Fixture()` and failed under Svelte 5 with `component_api_invalid_new`; the harness was corrected to use Svelte's `mount()` API before final captures. Earlier incomplete screenshots were discarded/replaced. The temporary Vite server and Chromium profile have been stopped/removed; screenshot files remain for review.
