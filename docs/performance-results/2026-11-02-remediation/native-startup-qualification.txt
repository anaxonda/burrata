Native startup and private audio qualification method
Date: 2026-11-02

Scope
- This harness measures first-track startup and verifies short native PCM output using isolated Linux app payloads and synthetic audio fixtures. It does not use a normal Burrata profile or establish physical-device behavior. Results identify the payload build profile; diagnostic evidence is not a release-build qualification.
- The separate 0/100 pending-quality-assets condition inserts zero or 100 hash-valid fixture assets whose quality-facts hashes are stale. Normal full-file hash verification remains enabled.

Capture phases and pass criteria
- Startup is timed as its own phase and must finish within 20 seconds. A subsequent PCM phase lasts 5–6 seconds; these phases are recorded separately.
- A case requires at least five seconds of playback progress tied to the same playback generation and at least 4.5 seconds of finite PCM captured from the private monitor. Provider identity, successful exit, and phase-window checks are also required.
- The startup comparison uses at least 20 measured samples per build and condition, with three warmups excluded. Baseline/final payload and 0/100 condition order are interleaved. A separate two-track natural-completion capture is reported outside startup timing.
- Captures use a fresh isolated profile and private virtual audio/display services. PCM evidence is an application output check in that private monitor; it is not physical output qualification.

Metrics and privacy
- Sanitized database snapshots retain only connection mutex scopes, counts/totals/maxima, per-callsite wait/hold metrics when available, and an explicit SQLite-engine-busy-wait status. Baseline global wait counters remain measured; baseline per-callsite operations and hold counters are null/unavailable, not zero.
- Optional idle IPC measurement observes only the registered WebView `ipc` signal for the target application process. It records numeric registration/count values, discards three one-second warmups, then reads 20 one-second buckets locally without MCP calls in the sampling loop. Payloads, URLs, and message contents are not inspected. Actual app idle counts remain pending.
- Raw traces, PCM captures, profiles, fixture JSON, and detailed logs are kept outside the release source snapshot.

Harness verification
- Native runtime capture tests: 30/30; startup qualification tests: 8/8; Node startup helper test passed. Python compilation, JavaScript syntax, and CLI help checks passed.
- These harness results validate the measurement code. They do not constitute a completed baseline/final optimized package comparison or physical audio-output qualification.
