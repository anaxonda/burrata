# Shared playback startup deadline

The implementation now passes one absolute monotonic startup deadline from the WebView resolution command through provider search, extraction, helper preparation, DNS and stream-access validation. Nested helper timeouts are capped by that instant; later stages do not receive a new startup budget. Native callers establish their own bounded operation deadline. The existing two-attempt foreground limit and recording/version/duration gates remain unchanged. No speculative extraction reserve was introduced.

Preflight cancellation and expiry checks prevent already-expired requests from polling helper setup or probes. Biased stage selection prefers cancellation and expiry before work. Resolver and command boundaries normalize deadline exhaustion so nested timeout messages do not replace the public startup-budget reason or lose the resolver deadline trace flag. Genuine caller cancellation remains distinct; late successful results are rejected after expiry.

The preview cache currently serializes identical misses behind a per-key gate, rather than hosting a detached shared worker. Each caller retains its own cancellation and deadline. A later caller can take over after the first expires, but may repeat work. This patch does not claim a detached extraction continues for remaining waiters.

Two independent read-only reviews identified and corrected expired-helper-start and timeout-normalization issues before integration. Regression cases cover those paths, an already-expired immediately ready success, nested helper deadlines, independent cancellation and queued callers. A separate Magalenha fixture exercises actual parsing/scoring/gates against sanitized public metadata.
