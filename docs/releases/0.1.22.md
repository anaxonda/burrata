# Burrata v0.1.22

This release fixes playback failures that could stop a track before audio began, and adds recording-aware Soulseek download waiting and lossless checks.

- Recover from native HTTP startup failures, expired source access, interrupted response bodies and empty media responses within the original startup deadline. Retries remain bounded; invalid byte ranges are still rejected.
- Play explicitly linked Bandcamp tracks through their selected source instead of rejecting them at the automatic-discovery gate. Matching uses fresh, separate artist and track fields and rejects contradictory page artists, wrong provider IDs and incompatible recordings.
- Report a missing local-only file clearly instead of falling through to online matching. Catalog-source fallback and pinned remote chapter sources retain their existing behavior.
- Configure **Wait for Soulseek** at its position in the download source order. Earlier sources still run; later sources wait for that recording, and other downloads continue.
- Optionally keep looking for a lossless copy after a permitted lossy download. Matching and decoded quality checks still apply, the saved copy remains available, and replacement respects playback ownership and the expected file hash. Both new policies default off.
- Manage waiting requests, lossless checks and review states in Downloads with compact menus. Saved free-text Soulseek searches move from the top of Settings to a dialog opened from Downloads.
- Show one current playback error with an information popup, distinguish unavailable rows from paused playback, and protect foreground diagnostics from background-preparation traffic.

See [Soulseek download policies](../soulseek-download-policies.md) and the [playback error audit](../playback-error-audit.md) for behavior and qualification details.

## Verification

The release workflow requires the complete native and frontend suites, installed-artifact audio checks on each platform, and an explicit live resolver check for the reported public Bandcamp recording. The live check complements deterministic HTTP, cancellation, cache, identity and queue-failure fixtures. Live Soulseek peer availability depends on the configured slskd connection and peers; a network-wide match is not guaranteed.
